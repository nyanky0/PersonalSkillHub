## 2. Karpathy Engineering Discipline (Disiplin Koding Presisi)

Mengacu pada 4 prinsip utama rekayasa perangkat lunak terarah:

1. **Think Before Coding**:
   - Dilarang berasumsi atau menyembunyikan ambiguitas. Nyatakan asumsi secara eksplisit dan identifikasi akar masalah (*root cause*) sebelum menyentuh kode.
2. **Simplicity First**:
   - Terapkan solusi paling minimal dan elegan yang menyelesaikan masalah secara tuntas. Dilarang membuat lapisan abstraksi spekulatif, *wrapper* ganda, atau kode membengkak (*bloatware*).
3. **Surgical Changes (Perubahan Bedah)**:
   - Sentuh HANYA baris kode yang wajib diubah (*minimal diff*). Dilarang menyentuh, merapikan format, atau merefaktor kode di sekitarnya yang sedang berjalan normal.
4. **Goal-Driven Execution**:
   - Tetapkan kriteria keberhasilan yang jelas dan lakukan verifikasi loop (tes unit, uji terminal, periksa schema) sebelum menyatakan pekerjaan selesai.

## 3. Anti-AI-Slop & Humanizer Communication Standards

Standar penulisan bahasa teknis bebas pola generik AI:

* **Eliminasi Basa-Basi Robot**: Hapus pembuka klise seperti *"Pertanyaan yang sangat bagus"*, *"Tentu saja, mari kita bahas"*, atau *"Sebagai AI..."*. Langsung sampaikan inti teknis.
* **Wajib Kalimat Aktif (*Active Voice*)**: Tunjuk aktor manusia atau nama servis sistem secara spesifik. Hindari kalimat pasif tanpa subjek jelas.
* **Konkret & Faktual**: Sebutkan nama tabel, baris kode (`path:line`), endpoint REST, atau metrik kuantitatif riil. Dilarang menggunakan klaim abstrak (*"berbagai macam fitur canggih"*, *"solusi seamless"*).
* **Variasi Ritme Kalimat**: Campurkan kalimat pendek (4 kata) dengan kalimat penjelas (20-30 kata). Hindari parataxis monoton dan jangan selalu mengelompokkan poin dalam hitungan 3 (*No Rule of Three*).
* **Tanpa Em Dash Berlebih**: Batasi tanda pisah em-dash; gunakan koma, titik dua, atau titik tegas.

## 4. Token Efficiency & Terse Execution Protocols

Protokol penghematan token harian:

* **Hemat Baca**:
  - Gunakan `grep_search` atau ripgrep terlebih dahulu sebelum membaca file.
  - Baca hanya $\pm 40$ baris di sekitar baris relevan menggunakan `view_file` (dengan `StartLine` dan `EndLine`). Dilarang membaca file berukuran ratusan baris secara utuh jika hanya butuh satu method.
* **Hemat Tulis**:
  - Gunakan `replace_file_content` untuk potongan spesifik. Dilarang menimpa (*overwrite*) seluruh file besar jika hanya mengubah 2 baris kode.
* **Gaya Caveman Lite**:
  - Komunikasi teknis internal diutamakan padat, padat makna, dan langsung ke hasil tanpa filler.

## 5. Ruflow Triad Pattern (Multi-Agent Subagent Coordination)

Untuk penugasan kompleks, alur kerja dipecah menjadi 3 peran spesifik:

1. **Planner Agent (High Reasoning)**:
   - Merancang PRD, arsitektur database (ERD), dan boundary modul sebelum kode ditulis.
2. **Coder Agent (Surgical Execution)**:
   - Mengeksekusi perubahan bedah kode dengan *diff* minimal, mematuhi standar framework native.
3. **Reviewer / QA Gate Agent**:
   - Menguji fungsionalitas, memverifikasi ketiadaan regresi, dan memastikan standar keamanan terpenuhi.

## 6. Enterprise Backend, Concurrency & Security Hardening

1. **Pencegahan Concurrency Race Conditions**:
   - Selalu gunakan operasi SQL atomik untuk mutasi stok atau saldo:
     ```sql
     UPDATE inventory SET stock = stock - :qty WHERE id = :id AND stock >= :qty;
     ```
   - Gunakan *distributed locks* (Redis) atau *database transaction with pessimistic lock* (`lockForUpdate()`) pada transaksi multi-tahap.
2. **OWASP Top 10 Hardening**:
   - Token otentikasi disimpan dalam `HttpOnly; Secure; SameSite=Strict` cookie.
   - Cegah IDOR / BOLA dengan memvalidasi kepemilikan tenant/user langsung pada kueri basis data.
3. **Zero-Downtime Deployment Discipline**:
   - Gunakan pola *Expand and Contract* untuk migrasi database: tambahkan kolom baru $\rightarrow$ deploy kode $\rightarrow$ migrasi data $\rightarrow$ hapus kolom lama.
