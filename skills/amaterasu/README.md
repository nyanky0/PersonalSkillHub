## 🇺🇸 English

### What is AMATERASU?

**AMATERASU** is a universal cognitive protocol that transforms any AI model into a world-class output engine. Activate it once, and every response becomes precision-engineered: zero filler, mandatory security, production-ready quality.

**One skill. Every model. Maximum output.**

<br>

### Why AMATERASU?

| Problem | Without AMATERASU | With AMATERASU |
|---------|------------------|----------------|
| Filler content | 15–30% of output | **0%** |
| Token usage | 100% baseline | **~45–60%** |
| Security coverage | Incidental | **Systematic (7 gates)** |
| Production readiness | ~50% | **90%+** |
| Output consistency | Variable | **Consistently high** |
| Time to actionable | Often slow | **Always immediate** |

<br>

### ⚡ The 8-Phase Protocol

```
ACQUIRE ──► MAP ──► ANALYZE ──► TARGET ──► EXECUTE ──► REVIEW ──► AMPLIFY ──► SEAL
```

| Phase | Name | Action |
|-------|------|--------|
| 01 | **ACQUIRE** | Lock context: task, constraints, success criteria, quality standard |
| 02 | **MAP** | Build solution architecture: strategy, steps, deps, risks, fallback |
| 03 | **ANALYZE** | Security threat matrix: injection, exposure, privilege, edge cases |
| 04 | **TARGET** | Eliminate noise: core problem ≠ symptoms, define scope lock |
| 05 | **EXECUTE** | Precision output: production-ready, zero placeholder, zero TODO |
| 06 | **REVIEW** | 6-checkpoint quality gate: correctness, security, perf, readability |
| 07 | **AMPLIFY** | Optimization pass: performance, hardening, polish, documentation |
| 08 | **SEAL** | Final delivery: TL;DR → main output → caveats → next steps |

<br>

### 🛡️ 7 Security Gates — Non-Negotiable

> Every AMATERASU output must pass all 7 gates. No exceptions.

```
SEC-01  INPUT VALIDATION    All input is untrusted until proven safe.
                            Sanitize before process. Validate before store.

SEC-02  ZERO TRUST OUTPUT   No internal state, stack traces, or config exposed.
                            User error messages ≠ developer error messages.

SEC-03  CREDENTIAL HYGIENE  Zero hardcoded credentials, tokens, passwords, keys.
                            Always env variables or secret managers.

SEC-04  INJECTION GUARD     SQL: parameterized queries always.
                            Shell: no string interpolation into commands.
                            XSS: escape all user content before HTML render.
                            Path: canonicalize and validate all file paths.

SEC-05  LEAST PRIVILEGE     Request minimum required permissions.
                            Scope tokens as narrow as possible.
                            Revoke access after use.

SEC-06  DATA PRIVACY        PII handling per applicable regulations.
                            Sensitive data not stored beyond necessity.
                            Encryption at rest and in transit.

SEC-07  DEPENDENCY SECURITY Check CVEs for all recommended libraries.
                            Pin dependency versions.
                            Prefer battle-tested over custom implementation.
```

<br>

### ⚡ Token Efficiency Rules

```
RULE-1  DENSITY      1 precise sentence > 3 vague ones
RULE-2  REFERENCE    [REF:n] to back-reference, never repeat
RULE-3  TABLE FIRST  Tables > long lists for structured data
RULE-4  CODE BEATS   Code directly > long explanation about code
RULE-5  NO REPEAT    Zero information repetition in one output
RULE-6  PROGRESSIVE  TL;DR first, detail on demand
RULE-7  OMIT OBVIOUS Don't explain what's obvious from context
RULE-8  SYMBOL USE   ◈ ☑ ✗ → ⚠ for visual hierarchy without extra words
```
