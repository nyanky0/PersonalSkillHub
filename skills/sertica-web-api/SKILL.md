# SERTICA Web API — integration skill

## Scope

SERTICA (Logimatic / Logihold) fleet-management Web API. ASP.NET Core, OpenAPI 3.0.4, api version `v1`.
Catalog captured from the live spec of the Indobaruna environment:

| Item | Value |
|---|---|
| Captured environment | `https://indobaruna-test.sertica.com` |
| Base path (`servers[0].url`) | `/api` |
| Example full URL | `https://indobaruna-test.sertica.com/api/PurchaseOrders` |
| Swagger UI | `/api/swagger/index.html` |
| Raw spec | `/api/swagger/v1/swagger.json` |
| Size of catalog | 2,743 paths / 3,340 operations / 1,104 schemas / 254 module tags |
| Auth | `Authorization: Bearer <accessToken>` (securityScheme `Bearer`, http bearer) |
| Offline spec copy | `assets/sertica-swagger.json.gz` (~340 KB gz of the 10.6 MB json) |

Verified: unauthenticated `GET /api/PurchaseOrders` returns **401** — every operation declares `security: [{Bearer: []}]`.

Load reference files only for the module you are integrating. Never read all of them at once:

- `references/endpoints-<nn>-<domain>.md` — every operation of that domain (method, path, summary, required user right).
- `references/endpoint-index.md` — one flat grep-able list of all 3,340 operations with their module tag.
- `references/core-models.md` — field lists of the 45 most-used request/response models.
- `references/models-index.md` — all 1,104 schema names + enum values.
- `references/patterns-and-integration.md` — auth, paging, search, documents, webhooks, error model + copy-paste code.
- `scripts/sertica_api.py` — offline lookup tool (search ops, show one op, dump a model).

## Auth flow

1. `POST /api/Auth` with the `SerticaUser` model:

```json
{ "login": "user", "password": "secret", "roleNo": null, "unitNo": null, "totpCode": null, "recoveryCode": null }
```

→ `200 JwtToken { "accessToken": "<jwt>", "expiresIn": 3600 }`; `400 ValidationResult` on bad credentials.

Send `login`/`password`, **not** `username`/`password` — wrong field names give `500 ArgumentNullException('key')` instead of 400.
2. Put the token in `Authorization: Bearer <accessToken>` on every other request.
3. `roleNo` / `unitNo` chosen at login scope the entire session — the same credentials with a different `unitNo` see a different data set.

Auth-adjacent endpoints: `GET /Auth` (current user), `GET /Auth/units` (unit/unit-group tree the user may access), `GET /Auth/userRights`, `GET /Auth/{login}/roles`, `POST /Auth/accessToken`, `GET /Auth/fileDownloadToken`, `GET /Auth/integrations`, `GET /Auth/officeSiteUrl`, password/pin reset + TOTP (`/Auth/totp/*`).

## Conventions (read out of the spec)

- **List**: `GET /api/{Module}?page=1&pageSize=25` → **bare JSON array**. `page` always defaults to 1; `pageSize` defaults to **25 on 450 operations and 5 on 177 operations** (e.g. `/PurchaseOrders/{no}/history`) — always send `pageSize` explicitly. There is no envelope and no `X-Total-Count` header anywhere in the spec — page until an empty/short array comes back. For a count use `POST /{Module}/searchCount`.
- **Detail**: `GET /api/{Module}/{key}` → object, `404` when unknown (`documentNo`, `jobNo`, `itemNo`, `componentNo`, `unitNo`, `guid` … per module, see the catalog paths).
- **Create / update / delete**: `POST /{Module}` → `201` + created object; `PUT /{Module}/{key}` → `200`; `DELETE /{Module}/{key}` → `204`. Bodies use the same model as the response (see `core-models.md`).
- **Advanced search**: `POST /{Module}/search` with `SearchDefinition`, `POST /{Module}/searchCount` → int, `GET|POST /{Module}/searchInfo` → searchable fields + operators per field. Full example in `patterns-and-integration.md`.
- **Sub-resources** hang off the detail path by suffix: `/history`, `/copy`, `/pdf`, `/file`, `/documents`, `/Documents`, `/checkout`, `/checkin`, `/approvers`, `/responses`, `/addResponse`, `/units`, `/children`, `/usage`, `/count`, `/positions`, `/propertyDefinitions`, `/listValues`, `/calculatedFields`, `/roles`, `/available`, `/retransmit`, `/reports`, `/resources`, `/appSubmit`, `/reject`, `/resolve`.
- **Binary / file endpoints** add `contentDisposition`, `filename`, `version`, `checkinWithoutVersion`, `revisionRemark`, `forceAutogenerateDocumentNo`, `imageDimension`, `imageQuality` query parameters.
- **Errors**: `400 ValidationResult { isValid, errors[], brokenRules[], subResults{} }`, `401` unauthorized, `403` missing user right, `404` not found, `500` unhandled (see SERTICA logs). 3,028 of 3,340 operations document their required right in the 403 description — it is captured as the **Rights** column of the endpoint catalogs.
- **Content types**: `application/json`, `text/json`, `text/plain` are offered everywhere; `application/json-patch+json` also appears on bodies. Send `Content-Type: application/json`.
- **Data shapes**: models are `SerticaWebApi.Models.*` DTOs with `additionalProperties: false` — unknown fields are rejected. Enum values are sent as **strings** (e.g. `SearchOperator`: `Equals, LessThan, GreaterThan, Like, Range, In, Dynamic, StartsWith, EndsWith, IsNull, NotLike, Or, NotEquals, NotIn`).

## Offline lookup (fastest path to an answer)

```bash
cd <skill_dir>
python scripts/sertica_api.py search 'invoice.*document'      # grep operations by path/summary
python scripts/sertica_api.py show GET /PurchaseOrders/{purchaseOrderNo}
python scripts/sertica_api.py rights PurchaseOrders            # which right each op needs
python scripts/sertica_api.py model PurchaseOrder              # fields of a model
python scripts/sertica_api.py refresh                          # re-download the spec from the environment
```

`scripts/build_references.py` regenerates all `references/*.md` from `assets/sertica-swagger.json.gz` — rerun both after a SERTICA upgrade.

## Pitfalls

- **User rights are per operation, not per module**: read the `Rights` column, or the integration will pass on one environment and 403 on the next. Rights also transitively need the license; the spec header warns that licensed-out endpoints may be absent entirely.
- `GET /api/swagger/v1/swagger.json` is the only reliable source of truth — the Swagger UI HTML page renders with JS and returns an empty shell to plain fetchers.
- Nothing in the spec documents rate limits, page-size maximums, or date/time formats. Treat `pageSize` values above a few hundred as unverified, and always test a date round-trip against the target environment before relying on it.
- Reference-list fields (e.g. `companyNo` + `companyName`) are read-only mirrors: send the `No`/`guid`, do not invent names.
- **Line/position collections are their own modules** (`PurchaseOrderPositions`, `RequisitionPositions`, `GET /ImInvoices/{invoiceNo}/positions`), not nested arrays on the header model — sync header and lines separately.
- `additionalProperties: false` on every model means a typo in a JSON key is a 400 at best, a silent drop at worst for nested arrays — diff your payload against `core-models.md`.
- No model declares `required` (0 of 1,104), so nothing warns you about a missing mandatory field until the server answers 400 with `brokenRules[]`.
